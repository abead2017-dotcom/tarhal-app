# ترحال

تطبيق نقل عربي مبني بـ Expo Router وReact Native وTypeScript، مع واجهة عربية RTL وخادم Express/tRPC وقاعدة MySQL عبر Drizzle. يتضمن مسارات الراكب والسائق والرحلات والموقع ومصادقة البريد وكلمة المرور عبر Gmail SMTP، مع إبقاء دخول المشرف عبر Manus OAuth. يتطلب تفعيل تسجيل البريد الحي إدخال بيانات Gmail وإعدادات الخادم.

> **حالة الإعداد:** الشيفرة وملفات البيئة النموذجية لا تحتوي بيانات اعتماد. لا يصبح تسجيل البريد حيًا قبل إعداد Gmail SMTP و`AUTH_SECRET`، ولا تصبح الرحلات قابلة للاستخدام قبل ضبط قاعدة بيانات MySQL وتشغيل الترحيلات على قاعدة مقصودة. لا تُعد ملفات EAS أو مسودة الخصوصية موافقةً أو إصدارًا للمتاجر.

## المتطلبات

- Node.js بإصدار LTS متوافق مع Expo SDK 57.
- `pnpm` بالإصدار المثبت في `package.json` (9.12.0).
- قاعدة MySQL متاحة للخادم.
- لحسابات البريد: حساب Gmail مع التحقق بخطوتين وكلمة مرور تطبيق، وعنوان إرسال معتمد.
- للخرائط على Android: مفتاح Google Maps مقيّد لمعرّف التطبيق وشهادات التوقيع.

## الإعداد المحلي

1. ثبّت الاعتمادات وأنشئ ملف إعداد خاصًا بهذه النسخة:

   ```bash
   pnpm install
   cp .env.example .env
   ```

2. أكمل المتغيرات المطلوبة في `.env` محليًا أو في مخزن أسرار الخادم. لا تضع القيم السرية في Git أو تطبيق الهاتف:

   - `DATABASE_URL`: رابط MySQL.
   - `MANUS_PROJECT_ID` و`MANUS_JWT_SECRET` و`MANUS_OAUTH_API_URL` و`MANUS_OAUTH_PORTAL_URL` و`OWNER_OPEN_ID`: لازمة لتدفق مشرف Manus OAuth وفق إعداد المشروع.
   - `AUTH_SECRET`: سر عشوائي فريد للخادم بطول 32 محرفًا أو أكثر، منفصل عن سر OAuth.
   - `SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM`: حساب Gmail وكلمة مرور التطبيق وعنوان المرسل الموثق. لا تستخدم كلمة مرور Gmail المعتادة.
   - `EXPO_PUBLIC_API_BASE_URL`: عنوان الخادم الذي يصل إليه العميل؛ يضبط المثال المحلي على `http://localhost:3000`، ويجب تغييره لعنوان يمكن للهاتف الوصول إليه عند اختبار جهاز فعلي، ثم إلى HTTPS للإصدار.
   - `EXPO_WEB_PREVIEW_URL`: أصل واجهة الويب المسموح به في CORS؛ المثال المحلي `http://localhost:8081`، ويجب ضبطه للأصل الفعلي عند الاختبار عبر شبكة أو النشر.
   - `GOOGLE_MAPS_API_KEY`: اختياري للتطوير على iOS، ومطلوب لخريطة Google على Android عند استخدام الميزة.

   يبيّن `.env.example` أسماء الإعدادات فقط ولا يحتوي أسرارًا صالحة.

3. بعد التأكد بعناية أن `DATABASE_URL` يشير إلى قاعدة التطوير المقصودة، طبّق الترحيلات:

   ```bash
   pnpm db:push
   ```

   **هذا الأمر يتصل بقاعدة البيانات ويغيّر مخططها؛** لا تشغّله على بيانات مشتركة أو إنتاجية دون مراجعة النسخة الاحتياطية وخطة الترحيل.

4. شغّل واجهة التطوير وAPI:

   ```bash
   pnpm dev
   ```

   يبدأ Metro بمعاينة الويب على المنفذ 8081 والخادم على المنفذ 3000. لاختبار شاشة الويب محليًا، افتح عنوان Metro الذي يعرضه الأمر. ولتشغيل Metro لهاتف، استخدم أمر Expo المناسب للشبكة والـdevelopment build لديك؛ التطبيق يتطلب بناءً أصليًا لاختبار GPS الخلفي، ولا تكفي معاينة الويب أو Expo Go لإثبات هذه الميزة.

## الفحوصات

```bash
pnpm check
pnpm lint
pnpm test
pnpm build
```

هذه الفحوصات لا ترسل بريدًا، ولا تنفذ ترحيلات، ولا تختبر أذونات GPS على هاتف فعلي. لم يُجرّب تسجيل SMTP حي أو بناء متجر ضمن هذا المستودع.

## مصادقة البريد

حسابات العملاء تستخدم البريد وكلمة المرور والتحقق وإعادة تعيين كلمة المرور. ترسل رسائل الرموز عبر Gmail SMTP عند اكتمال إعداد المتغيرات الثلاثة. تُحفظ أسرار الخادم فقط؛ لا تشارك كلمة مرور التطبيق في المحادثة أو المصدر. إذا لم تُضبط القيم، يجب أن يفشل مسار إرسال البريد بوضوح بدل الإيحاء بوصول رسالة.

يتطلب تفعيل المسارات للمستخدمين الحقيقيين نشر API عبر HTTPS، وتشغيل ترحيلات المصادقة على قاعدة البيانات الصحيحة، وإضافة الأسرار إلى منصة الاستضافة. لا تُجرى هنا رسالة اختبار حقيقية.

## الخصوصية والإصدار

`app/legal/privacy.tsx` مسودة وليست سياسة قانونية نهائية، وتحتوي حقولًا نائبة للجهة ووسائل التواصل. راجع `docs/store-readiness.md` قبل إصدار المتاجر؛ يلزم أيضًا رابط حذف حساب عام، واختبار على أجهزة فعلية، ومفاتيح خرائط مقيّدة وحسابات مطوّر. لا تُجرِ نشرًا أو بناءً أو إرسالًا للمتاجر دون موافقة مستقلة.
